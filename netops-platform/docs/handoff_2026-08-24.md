## 二、明日开发计划（方案 A：SNMP Trap 接收器）

### 2.1 目标
实现被动告警通道：设备主动发送 SNMP Trap → 平台接收 → 解析 → 生成告警。

### 2.2 新增/修改文件清单

#### 后端
| 文件 | 说明 |
|------|------|
| `app/trap_listener.py` | 核心监听循环、报文解析、规则匹配、生成 Alert |
| `app/models.py` | 新增 `SnmpTrapLog` 模型 |
| `app/routers/trap.py` | `GET /api/traps`、`GET/POST/DELETE /api/traps/rules` |
| `app/main.py` | startup 启动监听任务；shutdown 关闭 |
| `app/config.py` | 增加 `TRAP_LISTEN_PORT`、`TRAP_COMMUNITY` 等配置项 |
| `requirements.txt` | 已含 `pysnmp>=5.1.0`；当前环境安装的是 `7.1.29` |
| `backend/netops.db` | 新增表结构（启动时 `init_db` 自动创建） |

#### 前端（明日第二优先级）
| 文件 | 说明 |
|------|------|
| `frontend/src/pages/TrapLogs.tsx` | Trap 原始日志列表页面（可选，如告警中心已满足可先不做） |
| `frontend/src/components/Layout.tsx` | 侧边栏新增 "Trap 日志" 入口（可选） |
| `frontend/src/api.ts` | 增加 `fetchTrapLogs`、`fetchTrapRules`、`createTrapRule` 等接口 |

### 2.3 数据模型

#### `snmp_trap_log`
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID PK | |
| source_ip | str | Trap 来源 IP |
| source_port | int | 来源端口 |
| version | str | v1/v2c/v3 |
| community | str | v1/v2c community |
| security_level | str | v3 安全级别 |
| received_at | datetime | 接收时间（带时区） |
| pdu_type | str | Trap / Inform / TrapV2 |
| variables | JSON | OID-Value 列表 |
| raw_hex | str | 原始报文 hex |
| mapped_alert_id | str | 生成的告警 ID |

#### `trap_rule`（默认规则库，本期先做后端硬编码 + 简单 CRUD）
| 字段 | 说明 |
|------|------|
| id | UUID |
| oid_prefix | 匹配 OID 前缀，如 `1.3.6.1.4.1.2011` |
| severity | 1/2/3 |
| message_template | 告警标题模板 |
| enabled | bool |

### 2.4 默认 Trap 规则库（华为优先）
| OID 前缀 | 含义 | 默认级别 | 模板示例 |
|----------|------|----------|----------|
| `1.3.6.1.4.1.2011.2.13.1.1` | 华为 VRP 链路状态变化 | 2 | 接口 `{ifName}` 状态变化为 `{ifOperStatus}` |
| `1.3.6.1.4.1.2011.2.13.1.2` | CPU 利用率过高 | 1 | 设备 CPU 利用率突增 |
| `1.3.6.1.6.3.1.1.5.3` | 标准 linkDown | 2 | 接口链路 down |
| `1.3.6.1.6.3.1.1.5.4` | 标准 linkUp | 3 | 接口链路 up |

> 明日先做**硬编码规则表**，规则管理 UI 放在 Trap 模块验证通过后再补。

### 2.5 验证步骤
1. 后端启动日志出现 `SNMP Trap listener started on 0.0.0.0:162`。
2. 在华为设备上配置：
   ```
   snmp-agent target-host trap address udp-domain <后端IP> params securityname public v2c
   ```
3. 触发事件（如 shutdown 一个接口）。
4. 告警中心出现对应告警。

### 2.6 已知风险
- Windows 非管理员无法绑定 162 端口，开发/测试建议用 `1620` 或提升权限运行后端。
- 当前 `pysnmp` 版本为 `7.1.29`，API 与 4.x/5.x 差异较大，明日需先确认其异步 Trap receiver 写法。
